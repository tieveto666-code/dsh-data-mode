# 归因与组合 SOP

## 何时用计划模式

超过「1 个事实 + 1 个 B+ + 1 个归因」的问题，或用户要预测 / 长报告：先进入 plan mode，写出数据分析大纲，再执行。不要用编码计划原文。

## C — 归因

1. **先验证涨跌**。没有对比期时，用 ask_user 问，或默认环比并在回答里写明。只使用当前选中的数据源；未选中时不要列举 catalog 里的其它源。
2. 若事实不成立（没跌 / 没涨），纠正前提，停止往下拆。
3. 再向量、价、维度分解。贡献率要用该维度变化对总变化的贡献，**禁止用排行榜代替贡献率**。
4. 库里没有的外部因果（促销政策、竞品、天气等）直接说不知道，不要编故事。
5. 回答里写清本次计算公式；同一会话内口径保持一致。

## 组合问句

顺序固定：锁口径 → 一个事实查询 → 一个 B+ → 一个归因。
不要在同一轮塞进更多分解。

## 预测 / 长报告

不要做独立 ML 或假装能预测。把请求降级为若干可查的问数（历史趋势、同期、结构拆分），并标明不是预测模型。
